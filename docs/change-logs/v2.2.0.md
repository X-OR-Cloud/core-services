# v2.2.0 — 2026-05-09

## Features

- **sys**: P1 hoàn thành — module `setting` + lib `@hydrabyte/sys-client`.

### Sys service (P1.1–P1.8)

- **Setting schema** đầy đủ (key, value, scope, sensitive, encrypted/iv/authTag/keyVersion reserved cho Level 2). Unique compound index `{ key, scope, owner.orgId }`. Reuse `ConfigKey` enum từ `@hydrabyte/shared` để dual-read aiwm.configuration trong P5.
- **SETTING_METADATA** registry — migrate 28 keys từ aiwm + thêm `sensitive` flag (9 keys: S3 keys, SMTP password, *_API_KEY, OAuth tokens, Discord webhook URL, Telegram bot token, PinchTab API key) và `cacheTtlSec` per-key.
- **Service** với CRUD + RBAC (universe.owner / org.owner) + metadata-driven validation + bulk init.
- **Pub/sub publisher** `sys:setting:invalidate` + `sys:metadata:invalidate` — fail-soft (publish errors logged, not thrown).
- **UI controller**: 9 routes — public metadata (no auth) + JWT-protected list/detail/upsert/update/delete/reveal/initialize. Sensitive values masked trong list/detail; plaintext chỉ qua `POST /:key/reveal` (universe.owner).
- **Internal endpoints + 3 guards**:
  - `CidrAllowlistGuard` — env `SYS_INTERNAL_CIDR_ALLOWLIST`, fail-secure khi rỗng
  - `InternalApiKeyGuard` — `timingSafeEqual` chống timing attack, fail-secure khi env không set
  - `SecretRateLimitGuard` — Redis bucket 10/min per (IP+key), env `SYS_SECRET_READ_RATE_LIMIT` override, fail-open on Redis error
  - 2 endpoints: `GET /settings/internal/:key` (non-sensitive fallback), `GET /settings/internal/secret/:key` (sensitive). Cross-route mismatch → 404 với hint redirect (sensitive key trên route non-sensitive bị reject để không bypass rate limit).
- **Trust proxy** config `loopback, linklocal, uniquelocal` trong `bootstrap-api.ts` để `req.ip` không bị fake qua `X-Forwarded-For` từ internet.
- **Migration script skeleton** [`scripts/migrate-aiwm-config-to-sys.js`](../../scripts/migrate-aiwm-config-to-sys.js) — `--dry-run`/`--apply`, idempotent (skip key+scope+orgId đã có).

### Lib `@hydrabyte/sys-client` (P1.9–P1.17)

Mới: `libs/sys-client/`, export name `@hydrabyte/sys-client`, path mapping trong `tsconfig.base.json`.

- **`SysClientModule.forRoot({ sysApiUrl, internalApiKey, serviceName, mongoUri, redisUrl/host/port/pass, metricsEnabled?, ... })`** — global module.
- **`SysSettingClient`** — unified `get<T>(key, orgId?)` API, auto-detect sensitive qua metadata loaded from `GET /settings/metadata`. Helpers: `getString/getNumber/getBoolean/getOrDefault`, `getAll`, `has`, `reloadKey`, `reloadAll`, `getCacheStats`.
- **5 Safety Guards** non-negotiable (PROPOSAL §6.4) — verified in code review:
  1. **2 cache stores riêng** — `settingCache` (long TTL + stale-while-revalidate) vs `secretCache` (short TTL, no stale, always fresh)
  2. **`getAll()` skip sensitive** — bulk API never returns secrets
  3. **`redactValue()` helper** — wrapper for all log calls (in `redact.util.ts`)
  4. **Metrics no-value labels** — Prometheus labels chỉ `key`/`source`/`trigger`
  5. **`getCacheStats()` masked** — sensitive entries indistinguishable from non-sensitive in shape, no value field
- **Dual read paths**:
  - Non-sensitive: Mongo direct read (lib có connection riêng tới `core_sys`) + cache + stale-while-revalidate
  - Sensitive: HTTP `GET /settings/internal/secret/:key` với `X-Internal-API-Key` + `secretCache` ngắn (no stale)
- **Pub/sub subscriber** subscribe `sys:setting:invalidate` + `sys:metadata:invalidate`. Compute `pubsub_lag_seconds` histogram từ `updatedAt` payload.
- **In-flight de-dup** — concurrent `get()` cho cùng key chỉ 1 reload upstream (tránh thundering herd).
- **9 Prometheus metrics** (PROPOSAL §8.1): `sys_cache_hit_total`, `sys_cache_reload_total{trigger}`, `sys_cache_reload_duration_seconds`, `sys_pubsub_lag_seconds`, `sys_pubsub_disconnect_total`, `sys_setting_get_duration_seconds{type}`, `sys_secret_fetch_total{result}`. Idempotent registration (singleton).
- **`SysClientStatsController`** optional — debug endpoint `/sys-client/stats` (gated `DEBUG=true` hoặc `INTERNAL_API_KEY` header).
